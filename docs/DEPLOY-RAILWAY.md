# Развёртывание на Railway

Пошаговая инструкция: от репозитория на GitHub до работающего магазина с ботом и мини-приложением.
Времени нужно 15–20 минут. Писать код и пользоваться терминалом не придётся.

Что уже подготовлено в репозитории:

| Файл | Зачем |
|---|---|
| `Dockerfile` | образ `node:22-slim`; данные — в `/data`; приложение работает от пользователя `node` |
| `railway.json` | сборка из Dockerfile, проверка здоровья `GET /healthz`, перезапуск при сбое, один экземпляр |
| `scripts/container-start.mjs` | при старте делает том `/data` доступным для записи (Railway монтирует тома от root) и только потом запускает сервер без прав root |

Как приложение ведёт себя на Railway без дополнительных настроек:

- слушает порт из переменной `PORT` на всех интерфейсах (`0.0.0.0`);
- публичный адрес берёт из `BASE_URL`, а если она не задана — из `RAILWAY_PUBLIC_DOMAIN`, которую Railway
  подставляет сам (`https://<ваш-сервис>.up.railway.app`);
- доверяет одному прокси Railway (правильные IP-адреса посетителей, cookie с флагом `Secure`);
- базу `samo.db` и загруженные картинки `uploads/` хранит в одной папке `/data` — её и нужно положить на том;
- бот работает через long polling: вебхуки, дополнительные сервисы и планировщики не нужны.

---

## Шаг 1. Проект из репозитория

1. Зайдите на [railway.com](https://railway.com) → **New Project** → **Deploy from GitHub repo**.
2. Выберите репозиторий с проектом (при первом входе Railway попросит доступ к GitHub).
3. Railway найдёт `railway.json` и `Dockerfile` и начнёт первую сборку.

Первый запуск, скорее всего, завершится ошибкой — это ожидаемо: ещё не заданы обязательные переменные.
Переходите к следующим шагам.

## Шаг 2. Том для данных

Без тома база и загруженные картинки пропадают при каждом обновлении.

1. На холсте проекта нажмите **+ Create** (или правой кнопкой по пустому месту) → **Volume**.
2. Выберите сервис магазина.
3. **Mount path:** `/data` — именно так, без других вариантов.

Один том хранит всё: `/data/samo.db` и `/data/uploads/`.

## Шаг 3. Переменные

Откройте сервис → вкладка **Variables** → **Raw Editor** и вставьте список, заменив значения своими.

### Обязательные

| Переменная | Пример | Секрет | Пояснение |
|---|---|:---:|---|
| `SESSION_SECRET` | `4f1c…` (64 символа) | да | Случайная строка от 32 символов: подпись cookie и CSRF-токенов. Сгенерировать: `openssl rand -hex 32` или любым генератором паролей |
| `ADMIN_EMAIL` | `owner@example.uz` | нет | Логин первого администратора |
| `ADMIN_PASSWORD` | `Очень-длинный-пароль` | да | Пароль первого администратора, от 8 символов. Используется **один раз**, при создании учётной записи; потом пароль меняется в панели |
| `PORT` | `3000` | нет | Порт приложения. Его же укажете при создании домена |

### Для демо-стенда (показать продукт заказчику)

| Переменная | Значение | Пояснение |
|---|---|---|
| `ANALYTICS_RETENTION_DAYS` | `400` | нет | Сколько дней хранить сырые просмотры страниц (старые удаляются автоматически, `0` — хранить всё) |
| `SEED_ON_EMPTY` | `1` | При первом запуске наполняет **пустую** базу демо-данными: каталог, блог, заказы и аналитика за 60 дней. Базу, в которой уже есть товары, заказы или клиенты, не трогает никогда |
| `ALLOW_MOCK_PAYMENTS` | `1` | Включает демо-страницу оплаты. Без неё в production оформить заказ можно только с настроенной платёжной системой |

Для настоящего магазина обе переменные не задавайте (или удалите перед запуском).

### Telegram

| Переменная | Пример | Секрет | Пояснение |
|---|---|:---:|---|
| `BOT_TOKEN` | `7312345678:AAH…` | да | Токен из @BotFather (`/newbot`) |
| `BOT_USERNAME` | `samo_coffee_bot` | нет | Имя бота без `@` — для ссылок «Открыть в Telegram» |
| `ADMIN_CHAT_ID` | `-1001234567890` | нет | Чат команды: сюда приходят заказы, оплаты и обращения. Id группы начинается с `-100` |

Без этих переменных магазин работает, но бот, мини-приложение и уведомления выключены.

### Оплата (когда будете подключать)

| Переменная | Пример | Секрет | Пояснение |
|---|---|:---:|---|
| `PAYMENT_PROVIDER` | `payme` | нет | `mock`, `telegram`, `payme` или `click`. Можно переключать и в панели: *Настройки → Оплата* |
| `TELEGRAM_PAYMENT_TOKEN` | `398062629:TEST:…` | да | @BotFather → `/mybots` → бот → *Payments* |
| `PAYME_MERCHANT_ID` | `5e730e8e0b852a417aa49ceb` | нет | Id кассы из кабинета Payme |
| `PAYME_KEY` | `…` | да | Ключ кассы (пока `PAYME_TEST=1` — тестовый) |
| `PAYME_TEST` | `1` | нет | `1` — тестовый стенд Payme, `0` — боевой |
| `CLICK_SERVICE_ID` | `12345` | нет | Из кабинета Click |
| `CLICK_MERCHANT_ID` | `6789` | нет | |
| `CLICK_MERCHANT_USER_ID` | `1011` | нет | |
| `CLICK_SECRET_KEY` | `…` | да | |

### Что задавать не нужно

| Переменная | Почему |
|---|---|
| `NODE_ENV`, `DATA_DIR` | Уже заданы в образе: `production` и `/data` |
| `BASE_URL` | Берётся из домена Railway. Задайте её только для **своего домена**: `BASE_URL=https://shop.example.uz` (без `/` в конце) |
| `TRUST_PROXY`, `HOST` | На Railway правильные значения выбираются автоматически |
| `BOT_MODE` | По умолчанию `polling` — на Railway работает сразу |
| `TMA_DEV_AUTH` | Режим предпросмотра мини-приложения; в production игнорируется |

Пример для вставки в Raw Editor (демо-стенд с ботом):

```ini
SESSION_SECRET=замените-на-случайную-строку-из-64-символов
ADMIN_EMAIL=owner@example.uz
ADMIN_PASSWORD=замените-на-свой-пароль
PORT=3000
SEED_ON_EMPTY=1
ALLOW_MOCK_PAYMENTS=1
BOT_TOKEN=7312345678:AAH...
BOT_USERNAME=samo_coffee_bot
ADMIN_CHAT_ID=-1001234567890
```

После сохранения Railway пересоберёт и перезапустит сервис.

## Шаг 4. Домен

1. Сервис → **Settings** → **Networking** → **Generate Domain**.
2. Если спросит порт — укажите `3000` (значение `PORT`).
3. Появится адрес вида `https://samo-coffee-production.up.railway.app`.
4. Сделайте **Redeploy** (меню последнего деплоя → *Redeploy*), чтобы приложение узнало свой адрес.

Проверьте в логах деплоя (**Deployments → View logs**) первые строки:

```
[start] data dir /data is ready, running as node (uid 1000)
[samo] SEED_ON_EMPTY: demo data loaded (12 products, 490 orders, 4 posts)      ← только с SEED_ON_EMPTY=1; число заказов может отличаться
[samo] production · https://samo-coffee-production.up.railway.app (listening on 0.0.0.0:3000)
[samo] payments: mock · bot: polling · db: /data/samo.db · uploads: /data/uploads
[bot] @samo_coffee_bot is running (long polling)
```

На что смотреть: адрес начинается с `https://` и это ваш домен; база лежит в `/data/samo.db`; бот запущен.

Откройте сайт, затем `https://<домен>/admin` и войдите с `ADMIN_EMAIL` / `ADMIN_PASSWORD`.

**Свой домен.** *Settings → Networking → Custom Domain*, добавьте CNAME-запись у регистратора, затем задайте
переменную `BASE_URL=https://ваш-домен` и дождитесь перезапуска.

## Шаг 5. BotFather: бот и мини-приложение

1. **Бот.** [@BotFather](https://t.me/BotFather) → `/newbot` → имя и username → скопируйте токен в `BOT_TOKEN`,
   username — в `BOT_USERNAME`.
2. **Чат команды.** Создайте группу, добавьте в неё бота. Узнайте id группы (например, перешлите сообщение
   из неё боту [@getidsbot](https://t.me/getidsbot)) и впишите в `ADMIN_CHAT_ID`.
3. **Кнопка меню с мини-приложением.** Бот ставит её сам при запуске, когда у сайта HTTPS-адрес. Чтобы задать
   вручную или сменить подпись: @BotFather → `/setmenubutton` → выберите бота → отправьте URL
   `https://<домен>/tma/` → отправьте название кнопки, например «Магазин».
4. **Прямая ссылка на мини-приложение** (по желанию): @BotFather → `/newapp` → выберите бота → название,
   описание, картинка 640×360 → **Web App URL:** `https://<домен>/tma/` → короткое имя. Получится ссылка
   `https://t.me/<бот>/<имя>`.
5. **Описание и аватар бота:** `/setdescription`, `/setabouttext`, `/setuserpic` — по вкусу.
6. Напишите боту `/start`. Он ответит приветствием и покажет меню. Отправьте любое сообщение — оно появится
   в чате команды; ответьте на него (reply) — ответ придёт вам в бота.

`/setdomain` настраивать не нужно: он относится к виджету входа через Telegram, а мини-приложение
авторизуется подписью `initData`.

## Шаг 6. Платёжные системы

Адреса, которые нужно указать в кабинетах (подставьте свой домен):

| Провайдер | Что указать |
|---|---|
| Payme | Endpoint (URL для запросов Merchant API): `https://<домен>/pay/payme`. Поле счёта (account): `order_id` |
| Click | Prepare URL: `https://<домен>/pay/click/prepare`, Complete URL: `https://<домен>/pay/click/complete` |
| Telegram Payments | Адреса не нужны: @BotFather → `/mybots` → бот → *Payments* → выберите провайдера и скопируйте токен в `TELEGRAM_PAYMENT_TOKEN` |

После того как ключи заданы в **Variables**, выберите провайдера в панели: *Настройки → Оплата*. Там же видно,
каких ключей не хватает. Перед приёмом настоящих платежей пройдите проверку на тестовых стендах — порядок
описан в [PAYMENTS.md](PAYMENTS.md). Когда оплата настроена, удалите `ALLOW_MOCK_PAYMENTS`.

## Шаг 7. Переход от демо к настоящему магазину

Демо-данные удобны для показа, но в боевом магазине они не нужны. Самый чистый путь:

1. Удалите переменные `SEED_ON_EMPTY` и `ALLOW_MOCK_PAYMENTS`.
2. Удалите том (карточка тома → *Settings → Delete Volume*) и создайте новый с тем же путём `/data`.
3. Сделайте Redeploy. База создастся пустой, первый администратор — из `ADMIN_EMAIL` / `ADMIN_PASSWORD`.
4. Заполните каталог, тексты страниц и настройки в панели.

Тексты страниц после такого сброса — исходные демо-тексты: это шаблон, который вы редактируете в разделе
«Страницы».

## Обновление

Каждый `git push` в подключённую ветку запускает новую сборку и перезапуск. Данные на томе сохраняются.
Из-за тома Railway сначала останавливает старую версию, потом запускает новую — магазин недоступен несколько
секунд. Миграции базы применяются при запуске автоматически.

## Резервные копии

- Railway: карточка тома → **Backups** (ручные и по расписанию, зависит от тарифа).
- Заказы и клиенты выгружаются в CSV из панели (*Заказы → Экспорт*, *Клиенты → Экспорт*).

## Если что-то пошло не так

| Симптом | Причина и решение |
|---|---|
| Деплой падает, в логе `SESSION_SECRET (16+ chars) is required` | Не задана `SESSION_SECRET`. Добавьте переменную |
| Healthcheck failed / `Application failed to respond` | Смотрите логи деплоя: ошибка запуска будет там. Если приложение запустилось, проверьте, что порт домена совпадает с `PORT` (`3000`) |
| Не получается войти в панель, в логе `no admins exist and ADMIN_PASSWORD is empty` | Задайте `ADMIN_PASSWORD` и перезапустите. Учётная запись создаётся только когда администраторов ещё нет |
| Пароль в `ADMIN_PASSWORD` поменяли, а вход по-старому | Переменная действует только при первом запуске. Меняйте пароль в панели: *Профиль* |
| После обновления пропали товары и картинки | Не подключён том или путь не `/data`. В логе должно быть `db: /data/samo.db` |
| В логе `[start] /data is not writable for uid …` (или `unable to open database file`) | Контейнер запущен не от root, поэтому не может сам выдать права на том. Удалите переменную `RAILWAY_RUN_UID`, если она задана со значением не `0`, и перезапустите — скрипт запуска сам настроит права и сбросит root |
| Пароль администратора не принимается при первом входе, в логе `ADMIN_PASSWORD is shorter than 8 characters` | Пароль короче 8 символов — первый админ не создан. Задайте пароль длиннее и перезапустите |
| Рассылка из демо-стенда «не доходит» части получателей | С `SEED_ON_EMPTY=1` в базе есть вымышленные пользователи бота; Telegram отклоняет сообщения им, это нормально. На боевом стенде демо-данных нет |
| При оформлении заказа «Онлайн-оплата временно недоступна», в логе `payments: UNAVAILABLE` | В production демо-оплата выключена. Настройте провайдера или задайте `ALLOW_MOCK_PAYMENTS=1` для демо-стенда |
| Демо-данные не появились | `SEED_ON_EMPTY=1` срабатывает только на пустой базе. Если база уже создана — удалите том, создайте новый и сделайте Redeploy |
| Ссылки в сообщениях бота и после оплаты ведут на `localhost` | Приложение не знает свой адрес. Сделайте Redeploy после создания домена или задайте `BASE_URL` |
| Бот молчит, в логе `Telegram rejected BOT_TOKEN` | Неверный токен. Скопируйте его заново из @BotFather |
| Бот отвечает через раз, в логе `Conflict: terminated by other getUpdates request` | Тот же токен используется в другом месте (например, локальный запуск). Остановите вторую копию |
| У бота нет кнопки мини-приложения | Адрес сайта должен быть HTTPS и известен приложению (см. строку `[samo] production · https://…`). Перезапустите сервис или задайте кнопку через `/setmenubutton` |
| Мини-приложение в обычном браузере показывает «Откройте в Telegram» | Так и должно быть: в production вход возможен только из Telegram |
| Сообщения клиентов не приходят в чат команды | Проверьте `ADMIN_CHAT_ID` (для групп — со знаком минус) и что бот добавлен в группу |
| Payme или Click отвечают ошибкой авторизации / подписи | Ключи в Variables не совпадают с кабинетом; для Payme проверьте, что тестовый ключ используется с `PAYME_TEST=1`, а боевой — с `PAYME_TEST=0` |
| Аналитика показывает день со сдвигом | Часовой пояс задаётся `TZ_OFFSET_MINUTES` (Ташкент — `300`) |

Важно: держите **один экземпляр** сервиса (в `railway.json` так и задано) и не включайте режим
*Serverless / App Sleeping* — боту нужен постоянно работающий процесс.
