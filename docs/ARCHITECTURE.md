# Samo Coffee — architecture & contracts

This document is **the contract** between the foundation and the five modules (site, admin, bot,
mini app, payments). It describes what exists in the code today. If the doc and the code ever
disagree, the code (and its JSDoc) wins — fix the doc.

- Stack: Node.js 22, ESM JavaScript (no build step), Express 4, EJS, `node:sqlite`, grammY, multer,
  helmet, sanitize-html, chart.js, quill (both served from `/vendor`).
- One process runs everything: `src/server.js` → `createApp()` (site + admin + API + mini app static
  + payment endpoints) and `startBot(app)`.
- All user-facing text is Russian. Code/identifiers/comments are English.
- Money: **integer UZS sums** everywhere (`129000` → `formatSum()` → `"129 000 сум"`). Tiyin
  (`× 100`) only at the Payme / Telegram boundary (`sumToTiyin`, `tiyinToSum`).
- Timestamps: ISO-8601 UTC strings (`new Date().toISOString()`), `*_time` columns are epoch ms.
  Business-day grouping uses `TZ_OFFSET_MINUTES` (Tashkent, +300).

## 2. Request pipeline (`src/app.js`)

Order of middleware in `createApp({ bot = true })` (async, returns the Express app):

1. `GET /healthz` → `{ ok, uptime }`
2. Security headers (helmet). `res.locals.cspNonce` is set per request.
   - Default CSP: `default-src 'self'`; `script-src 'self' 'nonce-…'`; `style-src 'self' 'unsafe-inline'`;
     `img-src 'self' data: blob: https:`; `font-src 'self' data:`; `connect-src 'self'`;
     `frame-ancestors 'none'`; `form-action 'self'` + Payme/Click checkout hosts + `https://t.me`.
   - `/tma` and `/tma/*`: additionally `script-src https://telegram.org`, `frame-ancestors 'self'
     https://web.telegram.org https://*.telegram.org`, no `X-Frame-Options`.
   - **No inline `<script>` without a nonce.** Use external files (`public/<module>/js/*.js`) or
     `<script nonce="<%= cspNonce %>">`. Inline `style=""` attributes and `<style>` are allowed.
     Pass data to scripts with `<script type="application/json" id="x"><%- jsonForScript(data) %></script>`.
     Inline event handlers (`onclick=""`) are blocked — attach listeners in JS.
3. `compression`
4. Static files:
   | URL | Directory |
   |---|---|
   | `/vendor/chart.js/*` | `node_modules/chart.js/dist` (use `/vendor/chart.js/chart.umd.min.js`) |
   | `/vendor/quill/*` | `node_modules/quill/dist` (`quill.js`, `quill.snow.css`) |
   | `/fonts/playfair-display/*`, `/fonts/manrope/*` | `@fontsource/*/files` (referenced by tokens.css) |
   | `/uploads/*` | `config.uploads.dir` |
   | `/tma/*` | `public/tma` (`/tma/` serves `index.html`, never cached) |
   | `/*` | `public` (`index: false`, no directory redirects → `/admin` reaches its router) |
5. `cookie-parser` (signed with `SESSION_SECRET`), `express.json` (1 MB), `express.urlencoded`
   (`extended: true`, 2 MB). **`req.rawBody`** (Buffer) is available for JSON/urlencoded bodies.
6. `analytics.sessionMiddleware()` → `req.sessionId`, `req.device`, `req.isBot`, `req.traffic`
7. `flashMiddleware()` → `req.flash(type, message)`, `res.locals.flash`
8. `csrfProtection({ ignore: CSRF_IGNORE })` → see §8
9. View locals (see §3)
10. Routers: `/admin` → `/api/tma` → `/pay` → **`startBot(app)`** (may mount the webhook route) →
    `analytics.pageViewMiddleware()` → `/` (site router; it must end with its own 404 handler)
11. Fallback 404 and the error handler: `AppError`s (and any 4xx) expose `err.message`; JSON is
    returned for `/api/*`, XHR or `Accept: application/json` as
    `{ ok: false, error: <code>, message, details? }`, otherwise a small HTML error page.

`CSRF_IGNORE = [/^\/api\//, /^\/pay\/payme(\/|$)/, /^\/pay\/click(\/|$)/, /^\/pay\/telegram(\/|$)/, /^\/bot\//]`
`PAGEVIEW_EXCLUDE = ['/admin', '/api', '/pay', '/tma', '/bot', '/healthz']`
`COOKIELESS = ['/api', '/bot', '/pay/payme', '/pay/click', '/pay/telegram', '/healthz']` — these paths never
receive cookies (no analytics session, no CSRF cookie).

Async route handlers: Express 4 does not catch promise rejections — wrap with try/catch and `next(err)`.

## 3. Views (EJS)

`app.set('views', 'src')`, so render with a path from `src/`:
`res.render('site/views/home', {...})`, `res.render('admin/views/orders/list', {...})`.
Includes are relative to the including file: `<%- include('partials/header') %>`.

Available in **every** template (`res.locals`):

| Local | Meaning |
|---|---|
| `settings` | all settings `{ site_name, phone, email, address, social_instagram, … }` (§5.2) |
| `g` | content blocks of page `global` (`g.logo`, `g.announcement`, `g.footer_about`, …) |
| `appConfig` | `{ baseUrl, isProd, botUsername, botUrl, tmaUrl, tmaDevAuth }` |
| `currentPath`, `canonicalUrl`, `query` | request info |
| `csrfToken`, `csrfField` | token string / ready `<input type="hidden" name="_csrf" …>` (output with `<%- csrfField %>`) |
| `cspNonce` | nonce for inline scripts |
| `flash` | `[{ type: 'success'|'error'|'info'|'warning', message }]` (reading it consumes the messages) |
| `formatSum, formatNumber, formatCompact, discountPercent` | `lib/money.js` |
| `escapeHtml, nl2br, jsonForScript, stripTags, truncate, plural` | `lib/escape.js` |
| `formatDate, formatDateTime, formatDateShort, formatDateTimeFull, formatDayMonth, isoDate, timeAgo` | `lib/dates.js` (business timezone, ru) |

Admin router additionally gets `admin` (via `auth.loadAdmin`).

Output rules: `<%= %>` for everything; `<%- %>` only for sanitized rich text (`details_html`,
`body_html`, FAQ `answer`, `richtext` blocks), `nl2br()`, `csrfField`, `jsonForScript()`, includes.

## 4. Database

`src/db/index.js` exports:

| Export | Description |
|---|---|
| `db` | the shared `DatabaseSync` connection (WAL, foreign keys ON, busy timeout 5 s) |
| `get(sql, ...params)` / `all(sql, ...params)` / `run(sql, ...params)` | cached prepared statements, positional params, plain-object rows |
| `tx(fn)` | synchronous transaction (nested → savepoints). **Never `await` inside.** |
| `now()` / `iso(date)` | ISO timestamp helpers |
| `parseJson(text, fallback)` | safe JSON column parse |
| `migrate()` | runs `schema.sql` + `migrations/*.sql` once (called automatically on import) |
| `closeDb()` | close the connection |

SQL function `ulower(text)` is registered (Unicode lower-case) because SQLite `LIKE`/`lower()` are
ASCII-only: `WHERE ulower(name) LIKE ?` with a lower-cased needle.

## 7. Order & payment lifecycle

```
            createFromCart / createSubscriptionOrder
                              │
                              ▼
   status:   new ──► pending_payment ──► paid ──► processing ──► shipped ──► delivered
              │            │               └────────────┴────────────┴───────────┴──► refunded
              └────────────┴──► cancelled
   payment_status:  unpaid → pending → paid   (failed → retry → paid)   paid → refunded
```

1. **Create** — `orders.createFromCart(ref, input)` or `orders.createSubscriptionOrder(input)`:
   order `new` / `unpaid`; admins are notified; bus `order.created`.
2. **Start payment** — `payments.startPayment(order, { returnUrl?, providerId?, channel?, tgUserId? })`
   (`src/payments/index.js`) → `orders.markPendingPayment()` → `provider.createPayment()` →
   `{ provider, redirectUrl? , invoiceLink? }`.
   - Site: redirect the browser to **`order.pay_url`** (`GET /pay/order/:token[?return=/path]`) —
     it calls `startPayment` and redirects to the provider (mock: `/pay/mock/<tx>`).
   - Mini App: call `startPayment(order, { providerId: 'telegram', returnUrl: '/tma/…' })`; with
     `invoiceLink` → `WebApp.openInvoice(link)`, with `redirectUrl` → `WebApp.openLink(url)` /
     `location.href` (hosted page fallback). `returnUrl` must be a same-site path or start with `BASE_URL`.
3. **Result** — the provider (callback / webhook / bot update / mock page) calls:
   - success → **`orders.markPaid(orderId, { provider, txId, amount })`** — idempotent. In one DB
     transaction: order → `paid`, payment row → `paid`, stock decremented (product orders),
     subscription activated/extended (subscription orders), `purchase` event, history. After commit:
     notifications (admins + customer) and bus events `order.paid`, `subscription.activated`.
     `amount`, when passed, must equal `order.total` (`amount_mismatch` otherwise).
     Stock is **not reserved** by unpaid orders: a provider must refuse a payment for goods that ran
     out *before* the customer is charged (`orders.stockShortage(order)`; `startPayment` does it for
     every provider and throws `out_of_stock`). `markPaid` itself never fails on a shortage (the money
     is already taken): it takes what the stock has, stores it in `order_items.stock_taken` and
     alerts the admins.
   - failure → `orders.markPaymentFailed(orderId, { provider, txId, reason })` — order stays payable.
   - refund → `orders.refund(orderId)`.
4. **Return** — the customer lands on `returnUrl`, default **`/order/<public_token>`** — the SITE
   module must serve this page (status, items, "Оплатить" button → `order.pay_url` while `order.can_pay`).
5. **Fulfilment** — admin moves the order with `orders.setStatus()`; the customer gets Telegram
   messages for `processing`, `shipped`, `delivered`, `cancelled`, `refunded` when `order.tg_user_id` is set.

### Provider interface (`src/payments/providers/*.js`)

```js
export default {
  id: 'payme',                       // mock | telegram | payme | click
  title: 'Payme',
  isConfigured() { return Boolean(config.payments.payme.merchantId && config.payments.payme.key); },
  async createPayment(order, ctx) {  // ctx: { returnUrl (absolute, validated), channel, tgUserId }
    return { redirectUrl };          // or { invoiceLink } for Telegram
  },
};
```

Register it in `src/payments/index.js` (`registerProvider(provider)`). Registry API:
`registerProvider, getProvider(id), listProviders() → [{ id, title, configured, active }],
activeProviderId(), resolveProvider(preferredId?), startPayment(order, ctx), safeReturnUrl(url, order),
orderStatusUrl(order), invoicePayload, parseInvoicePayload`.
The active provider = setting `payment_provider` (Admin → Settings) or `PAYMENT_PROVIDER`. Outside
production an unconfigured provider falls back to `mock`; in production `payment_unavailable` is thrown.

Conventions for the real providers:

- **Payme**: endpoint `POST /pay/payme` (JSON-RPC, Basic auth `Paycom:<PAYME_KEY>`), account field
  `config.payments.payme.accountField` (default `order_id`) = **`orders.id`**; amounts in tiyin;
  store the transaction in `payments` (`provider_tx_id` = Payme id, `state`, `create_time`,
  `perform_time`, `cancel_time`, `reason`); PerformTransaction → `orders.markPaid(…, { provider: 'payme', txId, amount })`;
  CancelTransaction after perform → `orders.refund()`.
- **Click**: `POST /pay/click/prepare`, `POST /pay/click/complete` (form-encoded, md5 `sign_string`),
  `merchant_trans_id` = **`orders.id`**; amounts in sums.
- **Telegram**: provider `telegram` → `telegramPayments.createInvoiceLink(order)`; the BOT module
  answers `pre_checkout_query` with `telegramPayments.validatePreCheckout()` and handles
  `successful_payment` with `telegramPayments.handleSuccessfulPayment()`. Payload: `order:<orderId>`.
- **Mock** (done): `/pay/mock/<tx>` page with "pay / fail / back" buttons (`data-testid`:
  `mock-pay-success`, `mock-pay-fail`, `mock-pay-cancel`).

Webhook paths under `/pay/payme`, `/pay/click`, `/pay/telegram` are CSRF-exempt; `req.rawBody` is available.

**All four providers are implemented** (`src/payments/providers/{mock,telegram,payme,click}.js`). Cabinet
setup, URLs to register, error-code tables, the return/waiting pages and "how to add a provider" are in
**`docs/PAYMENTS.md`**. Additions to the contract above:

- More registry exports: `buildInvoiceParams(order, { needPhone? })` (Bot API fields for `sendInvoice` /
  `createInvoiceLink`), `providerReturnUrl(order)`.
- `startPayment()` re-reads the order from the DB, also throws `amount_invalid` (total must be a positive
  integer) and passes provider errors through (e.g. `TelegramError` — the Mini App falls back to the hosted page).
- Every attempt is a `payments` row: `created` when the customer is sent to Payme/Click (no `provider_tx_id`
  yet), adopted by `CreateTransaction` / `Prepare`; when an order gets paid all other open attempts are closed
  (bus `order.paid`).
- Extra routes: `GET /pay/return/:token` (the return URL given to Payme/Click — ignores the query string,
  reads the DB, shows a waiting page while a callback is in flight), `GET /pay/status/:token` (JSON for the
  waiting pages), `GET /pay/invoice/:token` ("pay in Telegram" page used when the site pays with the
  `telegram` provider; `/pay/order/:token` redirects there).
- The mock provider is OFF in production (`isConfigured()` false, `/pay/mock/*` → 404) unless
  `ALLOW_MOCK_PAYMENTS=1`.
- `app.use('/pay', paymentsErrorHandler)` (before the generic error handler) answers Payme/Click in their
  own protocol when the global body parsers reject a request.
- Payment log: `paymentLog(event, fields)` in `src/payments/log.js` — JSON lines, secrets masked.

## 8. Security helpers

**CSRF** (`lib/csrf.js`) — installed globally. Every unsafe request (POST/PUT/PATCH/DELETE) outside
`CSRF_IGNORE` must carry the token as body field `_csrf`, query `?_csrf=` or header `X-CSRF-Token`.

```ejs
<form method="post" action="/contacts"> <%- csrfField %> … </form>
<meta name="csrf-token" content="<%= csrfToken %>">   <!-- for fetch(): headers: { 'X-CSRF-Token': token } -->
```

Failure → 403 (`err.code === 'EBADCSRFTOKEN'`). `/api/tma/*` is exempt because it authenticates
with initData, not cookies — it must never trust cookies.

**Rate limiting** (`lib/ratelimit.js`): `rateLimit({ windowMs, max, key: (req) => string, message, json })`
middleware or the `RateLimiter` class (`hit(key)`, `peek(key)`, `reset(key)`). Use on login (built into
`auth.login`), feedback forms, checkout, cart mutations, the TMA API.

**Flash** (`lib/flash.js`): `req.flash('success' | 'error' | 'info' | 'warning', text)` then redirect;
the next rendered view reads `flash`.

**Input**: `clean(value, max)` for strings, `sanitizeRichText(html)` (already applied by services for
rich text fields), `escapeHtml`, `escapeTg` (Telegram HTML), `slugify` / `uniqueSlug`.

**Errors**: `throw new AppError(code, 'Русский текст', status, details)`; helpers `notFound(what)`, `invalid(message, details)`.

**Cookies in use**: `sc_sid` (analytics session), `sc_src` (first-touch source), `sc_csrf` (signed),
`sc_flash` (signed), `sc_cart` (signed), `sc_admin` (signed). All HttpOnly, SameSite=Lax, Secure when
`BASE_URL` is https.

## 9. Telegram conventions

- **All HTTP calls** to the Bot API go through `lib/telegramApi.js`:
  `call(method, params, { token, timeoutMs })`, `safeCall(...)` (returns `null` instead of throwing),
  `sendMessage(chatId, html, extra)`, `trySendMessage(...)`, `createInvoiceLink({...})`,
  `isConfigured()`, `TelegramError` (`code`, `description`, `isBlocked`). They honor `TELEGRAM_API_ROOT`.
- **grammY** must use the same root: `new Bot(config.bot.token, { client: { apiRoot: config.bot.apiRoot } })`.
- `startBot(app)` contract (`src/bot/index.js`): return quickly (never `await bot.start()`), do nothing
  when `config.bot.enabled` is false, in webhook mode mount the handler at `config.bot.webhookPath`
  (`/bot/webhook`, CSRF-exempt) and verify `X-Telegram-Bot-Api-Secret-Token` against
  `config.bot.webhookSecret`. `stopBot()` must be safe to call at any time.
- Messages use `parse_mode: 'HTML'`; escape user text with `escapeTg()`.
- Private chat id == Telegram user id; `orders.tg_user_id` / `feedback_threads.tg_chat_id` are where
  notifications and replies go.
- Bot state machine lives in `tg_users.state` (`''` idle, `'support'` feedback mode, `'checkout'`,
  `'link_order'`) via `tgUsers.setTgState` (`src/bot/state.js`). A checkout / phone confirmation that
  nobody touched for 45 minutes expires (`expireStaleFlow`), so an abandoned flow never swallows later
  messages; a question typed in the middle of a flow is passed to support, not taken for input.
- **Feedback flow**: user message in support mode → `feedback.receiveFromTelegram({ tgUser, text, tgMessageId })`
  (stores + forwards to `ADMIN_CHAT_ID`, remembers the forwarded message id) → admin **replies to that
  message** in the admin chat → bot: `feedback.findThreadByAdminMessageId(msg.reply_to_message.message_id)`
  → `feedback.reply(thread.id, { text, via: 'telegram' })` → the user receives the answer. Replies from the
  admin panel use the same `feedback.reply(..., { adminId, via: 'panel' })`.
  Follow-ups: the id of a staff answer is stored too (`feedback.setAdminMessageId`), so a reply to one's
  **own** answer, or to the bot's confirmation "✅ Ответ доставлен · обращение #N", reaches the same
  thread. A reply to a colleague's answer is staff talk and goes nowhere; a reply to a bot message that
  belongs to no thread gets a hint in a staff group (in the owner's private chat it is a normal customer message).
- **Deep links**: `/start <param>` → `tgUsers.upsertTgUser(user, { startParam })` + `trackEvent('bot_start', { channel: 'bot', tgUserId, meta: { start_param } })`.
- **Mini App auth** (`lib/initData.js`): the client sends `Authorization: tma <Telegram.WebApp.initData>`.
  Server: `resolveTmaUser(req)` → `{ user, dev, startParam }` or `{ user: null, reason }`.
  `validateInitData(raw, botToken, { maxAgeSeconds })` checks the HMAC and `auth_date` freshness
  (`TMA_INITDATA_MAX_AGE`, default 24 h). `signInitData(fields, botToken)` builds valid data for tests.
  **Dev preview**: with `TMA_DEV_AUTH=1` and `NODE_ENV != production`, requests without initData are
  authenticated as `DEV_TMA_USER` (id `700000001`); `appConfig.tmaDevAuth` / `GET /api/tma/ping → dev`
  tell the client. In production the flag is ignored.
- Mini App URL: `config.tma.url` (`BASE_URL/tma/`). Telegram requires HTTPS for Mini Apps, URL buttons
  and webhooks — notification buttons are only added when `BASE_URL` is https.
- **Payments in Telegram**: see §7 (`services/telegramPayments.js`).

## 13. Running and testing

```
npm run seed     # reset + demo data (refuses in production without --force)
npm start        # node src/server.js
npm run dev      # node --watch
npm test         # node:test, files tests/**/*.test.js, one process per file
npm run art      # regenerate SVG artwork
```

Demo admin after seeding: `admin@samo.coffee` / `admin12345` (dev default).
Settings and content blocks are cached in memory: **restart the server after `npm run seed`** (or after
editing those tables from another process).

**Manual testing while several modules are being built in the same tree** — never use the default
port/database. Use the port and database assigned to your module, e.g.

| Module | PORT | DATABASE_PATH |
|---|---|---|
| foundation | 4100 | `./data/foundation-test.db` |
| site | 4101 | `./data/site-test.db` |
| admin | 4102 | `./data/admin-test.db` |
| bot | 4103 | `./data/bot-test.db` |
| mini app | 4104 | `./data/tma-test.db` |
| payments | 4105 | `./data/payments-test.db` |

```
PORT=4101 BASE_URL=http://localhost:4101 DATABASE_PATH=./data/site-test.db npm run seed
PORT=4101 BASE_URL=http://localhost:4101 DATABASE_PATH=./data/site-test.db npm start
```

**Automated tests** (`tests/<module>-*.test.js`) — helpers in `tests/helpers/`:

- `env.js` — **import first** in every test file: in-memory DB, test secrets, bot disabled.
- `env-telegram.js` — import first *instead* when the test needs a configured bot; exports
  `FAKE_TG_PORT`, `BOT_TOKEN`, `ADMIN_CHAT_ID` and points `TELEGRAM_API_ROOT` to the fake server.
  (Do not use top-level `await` before importing `src/**` — ESM siblings would load with the wrong env.)
- `fakeTelegram.js` — `startFakeTelegram(port)` → `{ calls, callsTo(method), on(method, handler), pushUpdate(update), reset(), close() }`.
- `http.js` — `startTestApp({ bot })` → `{ app, baseUrl, client, newClient(), close() }`; the client keeps
  cookies, picks up CSRF tokens from rendered forms (`postForm`, `postJson`) and replays absolute
  `BASE_URL` redirects against the test server.
- `fixtures.js` — `makeCatalog(n, overrides)`, `makePlan(overrides)`, `CUSTOMER`, `DELIVERY`.

Each test file runs in its own process with its own in-memory database; create the data you need
(fixtures or `seed({ quiet: true })` from `src/db/seed.js`).
